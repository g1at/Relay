# Relay 定时任务（Scheduled Tasks）方案

> 对标 OpenClaw 的 Gateway 内置 cron，结合 Relay「单进程 Electron 桌面应用」现状落地。
> 目标：尽可能复刻 OpenClaw 的无人值守自治能力，但**零新增运行时依赖**、复用现有 `claude:run` 链路。

---

## 0. 一句话结论

OpenClaw 靠「**常驻 Gateway 守护进程 + SQLite 持久 cron + isolated/custom session**」实现无人值守。
Relay 已经具备等价底子——**托盘常驻进程** + `jobs` Map + `claude:run` spawn `claude -p`（headless）+ `userData` 下的 JSON 持久化。
所以我们**不引入 SQLite、不引入独立守护进程**，只补三层：

```
┌─────────────────────────────────────────────────────────────┐
│  ① 调度器 Scheduler   （main 进程内的 setTimeout 轮子 + 错过补跑） │
│  ② 任务持久化 Store   （schedules.json，原子写，复用现有套路）     │
│  ③ 执行 + 投递 Runner （复用 claude:run / image:generate + 通知）│
└─────────────────────────────────────────────────────────────┘
```

外加一项系统集成：**Windows 开机自启**（让调度器尽量常驻），解决「应用没开着就错过任务」。

---

## 1. 现状盘点（为什么这么设计）

读过 `main.js` / `preload.js` / `renderer` 后确认的关键事实：

| 现有能力 | 位置 | 对定时任务的意义 |
|---|---|---|
| 托盘常驻：关窗口=隐藏到托盘，子进程继续跑 | `main.js` `win.on('close')` / `window-all-closed` | **调度器可以一直活着**——这正是 OpenClaw 用守护进程换来的东西，Relay 白捡 |
| `claude:run`：spawn `claude.exe -p --output-format stream-json`，按 `jobId` 索引，事件流回传 | `main.js:533` | 定时任务的「执行器」直接复用它，**一行不改地拿到** agent/工作目录/模型档/记忆/飞书 MCP |
| `image:generate`：OpenAI 兼容文生图，落盘 `generated_images/` | `main.js:1017` | 「定时出图」任务复用它 |
| JSON 原子写持久化（history.json / app-settings.json） | `readHistory`/`writeAppSettings` | `schedules.json` 照抄这套，**无需 SQLite** |
| 并发上限 `MAX_PARALLEL_JOBS=3` + `jobs` Map | `main.js:156` | 定时任务触发要排队，避免和用户手动对话抢配额 |
| 托盘菜单动态显示任务数 | `refreshTrayMenu` | 顺手加「下一个定时任务：xx:xx」一行 |
| 系统通知能力（`displayBalloon`） | `main.js:443` | 任务完成/提醒的投递载体之一 |
| preload `contextBridge` 暴露 `window.api.*` | `preload.js` | 新增 `window.api.scheduler.*` 照现有命名 |

**核心矛盾点（必须正视）**：
- OpenClaw 是**真守护进程**（launchd/systemd），关机重启自动拉起；Relay 是用户开/关的桌面应用。
  → 用 **Windows 开机自启 + 错过补跑** 弥补（见 §6）。
- 我们的默认网关（mify / `api.llm.mioffice.cn`）**撑不住派生调用**：子 agent、WebSearch、WebFetch 实测全挂（见记忆 `reference-openclaw` / `relay-spinner-hang-diagnosis`）。
  → isolated「agent 轮 + 工具」类任务要**显式提醒用户**：需要联网/子 agent 的自治任务请切换到能扛的模型档（如桌面版官方 Pro 链路），否则任务会半路失败。这是设计约束，不是 bug。

## 2. 数据模型

存储：`app.getPath('userData')/schedules.json`，原子写（`.tmp` + rename），UTF-8 无 BOM——与现有 `writeAppSettings` 完全一致。

```jsonc
{
  "version": 1,
  "tasks": [
    {
      "id": "uuid",
      "name": "每日新闻摘要",                    // 用户起的名，列表/通知显示
      "enabled": true,                          // 暂停开关（不删任务，只停触发）

      // ── 调度（对标 OpenClaw 三种 + tz）──
      "schedule": {
        "kind": "cron",                         // 'at' | 'every' | 'cron'
        "at": null,                             // kind=at：ISO 时间字符串或相对 "20m"/"2h"
        "everyMs": null,                        // kind=every：固定间隔毫秒
        "cron": "0 9 * * *",                    // kind=cron：5 段表达式（分 时 日 月 周）
        "tz": "Asia/Shanghai",                  // 时区（默认取系统时区）
        "jitterSec": 0                          // 顶点抖动（对标 OpenClaw 整点 ±5min，默认 0=精确）
      },

      // ── 执行 payload（对标 OpenClaw 的 isolated/session/command）──
      "action": {
        "type": "chat",                         // 'chat' | 'image' | 'command'
        // type=chat：复用 claude:run
        "prompt": "汇总今天的科技新闻，3 条要点",
        "sessionMode": "isolated",              // 'isolated'=每次全新；'session'=持久累积上下文
        "sessionRef": null,                     // sessionMode=session 时，绑定的会话 id（跨次 --resume）
        "mode": "plain",                        // 'plain' | 'agent'（复用现有 claude:run 语义）
        "agentName": null,                      // mode=agent 时的子智能体名
        "model": "haiku",                       // 'haiku'|'sonnet'|'opus'（注意派生调用网关限制）
        "workingDir": null,                     // 工作目录（复用现有 cwd / --add-dir 逻辑）
        // type=image：复用 image:generate
        "imageModel": null, "size": null, "n": 1,
        // type=command：纯脚本不起模型（对标 OpenClaw command；需用户在设置里显式开启“允许命令任务”）
        "command": null
      },

      // ── 投递（对标 OpenClaw announce/webhook/none）──
      "delivery": {
        "notify": true,                         // 系统通知 + 应用内角标
        "saveToHistory": true,                  // 结果落进一条会话历史（chat 类）
        "webhook": null                         // 可选：POST 结果到 URL（对标 OpenClaw webhook）
      },

      // ── 运行时状态（调度器维护，持久化以支持错过补跑）──
      "createdAt": "ISO",
      "updatedAt": "ISO",
      "lastRunAt": null,                        // 上次实际触发时间
      "lastStatus": null,                       // 'ok' | 'error' | 'skipped'
      "lastError": null,
      "nextRunAt": "ISO",                       // 下次预定触发（启动补跑判断 + 托盘显示用）
      "runCount": 0
    }
  ],
  "runs": [                                     // 最近 N 条执行历史（环形，上限如 200），对标 OpenClaw cron runs
    { "taskId": "...", "at": "ISO", "status": "ok", "ms": 12345, "summary": "...", "error": null }
  ]
}
```

设计要点：
- **`nextRunAt` 持久化**是错过补跑的关键：启动时比对 `nextRunAt < now` 即知错过了哪些。
- **不放 SQLite**：个人助手量级（几十条任务 + 200 条历史）JSON 完全够，且零依赖、可人工审计（与记忆库/历史一致的产品哲学）。

## 3. 调度器（main 进程内）

新增 `scheduler.js`（被 `main.js` require），对外暴露 `initScheduler()` / CRUD / `computeNextRun()`。

### 3.1 计时策略——单一 timer，不每任务一个 setInterval

```
loadStore() → 对每个 enabled 任务算 nextRunAt → 取最早的那个
  → setTimeout 到「最早 nextRunAt」唤醒
  → 唤醒后：跑到点的任务 → 重算它的 nextRunAt → 落盘 → 重新 arm 最早 timer
```

理由：
- `setInterval` 在系统休眠/时钟漂移下会累积误差；**每次重算 + 单 timer** 更稳，也好做抖动和补跑。
- `setTimeout` 上限 ~24.8 天，超长间隔分段重 arm（极少见，兜底即可）。

### 3.2 cron 表达式解析——自己写一个极简解析器，不引依赖

OpenClaw 用 croner。但 Relay 零依赖是产品红线（`package.json` `dependencies: {}`）。
方案：实现一个 ~120 行的 5 段 cron 解析器（`*`、`*/n`、`a,b,c`、`a-b`、具体值），覆盖个人助手 99% 用法：
- `0 9 * * *` 每天 9:00
- `*/30 * * * *` 每 30 分钟
- `0 9 * * 1-5` 工作日 9:00
- `0 9,18 * * *` 每天 9:00 和 18:00

时区：用 `Intl.DateTimeFormat(tz)` 把「当前时刻」投影到目标时区的字段做匹配——Node 内置，无需 tz 库。
> 复杂表达式（秒级、L/W/# 等）暂不支持，UI 上给「每天/每周/每 N 分钟/自定义 cron」预设，自定义里写明支持子集。

### 3.3 执行——复用现有链路，但走「无 webContents」的内部调用

现有 `claude:run` 是 IPC handler，依赖 `event.sender` 回传事件。定时任务触发时**可能没有窗口**（隐藏到托盘，webContents 仍在；但更稳妥是不依赖它）。

重构：把 `claude:run` 的 spawn 主体抽成纯函数 `runClaudeJob({...opts, onEvent})`：
- IPC handler 调它，`onEvent` = 转发到 `event.sender`（现有行为不变）。
- 调度器调它，`onEvent` = 收集流式输出累积成最终文本 + 落历史 + 触发投递；同时若主窗口在，也 `mainWindow.webContents.send` 推一个「定时任务跑完」事件让 UI 刷新。

这样**一套执行逻辑两个入口**，不重复维护，且定时任务自动继承：记忆注入、飞书 MCP 提示、ASK/IMAGE_HINT、agentProjects 知识库、工作目录授权、模型档映射——全都白拿。

并发：定时任务进 `jobs` Map 占配额；若触发时已满 `MAX_PARALLEL_JOBS`，**排队**（push 到内部 pending 队列，有空位再跑），并记 `lastStatus` 不直接判错。

### 3.4 session 模式（对标 OpenClaw isolated / session）

- `isolated`：不传 `sessionId`，每次全新上下文。适合「每日摘要」「定时出图」这类无状态后台活。
- `session`：首次跑生成并存 `sessionRef`，后续 `--resume sessionRef` 累积上下文。适合「每日站会，记得昨天说过什么」。复用现有 `--resume` 机制，sessionRef 存进 task。

## 4. IPC 与 preload

`main.js` 新增一组 handler，`preload.js` 暴露 `window.api.scheduler.*`（照搬现有 `history`/`data` 风格）：

```js
// preload.js 追加
scheduler: {
  list:    ()        => ipcRenderer.invoke('sched:list'),
  get:     (id)      => ipcRenderer.invoke('sched:get', id),
  create:  (task)    => ipcRenderer.invoke('sched:create', task),
  update:  (id, patch) => ipcRenderer.invoke('sched:update', { id, patch }),
  remove:  (id)      => ipcRenderer.invoke('sched:remove', id),
  toggle:  (id, enabled) => ipcRenderer.invoke('sched:toggle', { id, enabled }),
  runNow:  (id)      => ipcRenderer.invoke('sched:runNow', id),     // 立即手动跑一次（测试用）
  runs:    (id)      => ipcRenderer.invoke('sched:runs', id),       // 执行历史
  preview: (schedule) => ipcRenderer.invoke('sched:preview', schedule), // 预览未来 5 次触发时间
  onUpdate:(handler) => { /* 监听任务状态变化，UI 实时刷新 */ },
},
```

`sched:preview` 让用户填完 cron 能立刻看到「下次触发：今天 21:00、明天 09:00…」——降低 cron 表达式的认知门槛。

## 6. 离线/常驻策略（按你的选择：Windows 开机自启）

### 6.1 开机自启
用 Electron 内置 `app.setLoginItemSettings`（Windows 走注册表 Run 键，无需额外权限）：

```js
app.setLoginItemSettings({
  openAtLogin: true,
  args: ['--autostart'],     // 自启时静默最小化到托盘，不弹主窗
});
```

- 在设置页加开关「开机自动启动（后台运行定时任务）」，默认**询问后开启**（首次创建定时任务时提示一次）。
- `--autostart` 启动参数：跳过主窗口显示，直接建托盘 + 起调度器（仿现有 `IS_DEV` 判断那样加 `IS_AUTOSTART`）。

### 6.2 错过补跑（catch-up）
启动 `initScheduler()` 时：
```
对每个 enabled 任务：
  若 nextRunAt 存在且 < now（说明应用没开着时错过了）：
    - 一次性任务(at)：补跑一次（或按设置“错过即跳过”）
    - 周期任务：默认只补跑“最近错过的那一次”（不把睡一晚错过的 48 次全补上——会刷屏），
      然后重算下一个未来的 nextRunAt。是否补跑做成任务级选项 catchUp: true/false。
  否则正常 arm。
```
> 这是和 OpenClaw 真守护进程的最大体感差距，但「自启 + 补跑最近一次」对个人助手足够，且不会半夜轰炸通知。

## 9. 风险与注意

1. **网关派生调用限制**（最重要）：mify/mimo 档跑「需要联网或子 agent 的 isolated agent 任务」会半路挂。
   → 创建 Agent/联网类定时任务时，UI 显式提示「此类任务建议用官方 Pro 链路/能扛派生调用的模型档」。记忆 `reference-openclaw`、`feedback-relay-desktop-vs-cli-channel` 已记录此坑。
2. **转圈/异常收尾**：定时任务无人盯着，执行器必须有 try/catch 包住流式渲染解析（参考 `relay-spinner-hang-diagnosis` 里 `marked.parse` 抛异常关不掉转圈的教训），失败要稳稳记 `error` 而不是静默卡死。
3. **通知轰炸**：周期任务错过多次只补跑最近一次；通知做节流。
4. **并发抢占**：定时任务占 `MAX_PARALLEL_JOBS` 配额，触发时满了要排队，别让定时任务把用户手动对话挤掉（或反之）。
5. **时钟/休眠**：单 timer + 每次重算 nextRunAt，规避 setInterval 漂移；从休眠唤醒时主动重算一次。
6. **命令任务安全**：`type=command` 默认禁用，开启需用户在设置里显式打开并确认风险（任意脚本执行）。

## 9.5 从 Claude 桌面版真实实现校准的设计（重要）

> 来源：本机 Claude 桌面客户端**原生内置**的定时任务系统（`mcp__scheduled-tasks__*` / `CronCreate`，
> 任务存为 `~/.claude/scheduled-tasks/{taskId}/SKILL.md`）。它是生产级实现，能力几乎一对一对标 OpenClaw cron。
> Relay 背后 spawn 的 `claude -p`（headless）**吃不到**这套（它属于桌面 App 的 GUI 层），所以 Relay 仍需自造；
> 但这套真实实现把几个原本「对着 README 猜」的设计点给了**确定答案**，逐条固化如下。

1. **⭐ prompt 必须完全自包含（最高优先级）**
   桌面版工具描述原文：*"Each run starts fresh with no memory of this conversation, so the prompt must be fully self-contained: include which connectors to use, the output format, and any preferences."*
   → Relay 的定时 `action.prompt` 同理：isolated 轮没有任何对话上下文，prompt 里要**自带**所需的 agent 名、工作目录、输出格式、用户偏好。UI 的 prompt 输入框旁给提示文案，避免用户写「像刚才那样」这类依赖上下文的指令。

2. **⭐ 一次性任务触发后自动归档**
   桌面版 `fireAt` 触发后**自动 `enabled=false`**；并强调**绝不能用 cron 表达一次性**（cron 无单次语义）。
   → Relay 的 `kind='at'` 跑完即置 `enabled=false`（不删，留痕可见），不让它复活。UI 上「一次性/周期」是互斥单选，别让用户用 cron 凑一次性。

3. **⭐ 周期任务默认轻抖动（不死磕整点）**
   桌面版**默认就抖**：避开 :00/:30，recurring 最多迟 period 的 10%（上限 15min）。理由原文大意：*每个说「9am」的用户都拿到 `0 9`，全球请求同一刻砸向 API*。
   → 这个理由对 Relay 走的 **mify 网关同样成立**。修正：`jitterSec` 默认**不再是 0**，而是对「整点/半点」类 cron 自动加几分钟随机抖动；只有用户明确要求精确时刻（如对齐会议）才关。

4. **错过补跑 = 下次启动补跑，且明确告知用户**
   桌面版原文：*"Scheduled tasks run while this app is open. If the app is closed when a task is due, it runs on next launch."* —— 印证了我 §6 的方向是对的。
   → 补一条**产品要求**：UI 必须显式写明「应用没开着时，到点的任务会在下次启动 Relay 时补跑一次」，别让用户惊讶。这正是 Relay（非守护进程）与 OpenClaw（真 daemon）体感差异的诚实交代。

5. **cron 语义确认无误**：5 段 `分 时 日 月 周`、**本地时区不转 UTC**、`fireAt` 用 ISO 8601 带时区偏移——与我方案 §2/§3 完全一致，可放心实现。

6. **任务即 Skill（设计参考，不强求照搬）**
   桌面版把每个任务落成一个 `SKILL.md`（带 frontmatter + 正文 prompt）。Relay 可以继续用更轻的 `schedules.json`；
   但若未来想让定时任务**复用 Relay 已有的技能/Agent 导入体系**，「任务=Skill 目录」是一条值得评估的演进路线（与你 `~/.claude/skills`、`data:importZip` 那套天然契合）。本期不做，记为 P3 备选。

## 10. 决策（已拍板 — 2026-06-09）

1. **P0 范围 = 最小集**：`type=chat` + `sessionMode=isolated` + 三种调度（cron/at/every）+ 完成通知 + 存历史。先跑通「每天定点出摘要 → 弹通知 → 落历史」。
2. **命令任务 `type=command`**：**放 P2，默认关闭**（任意脚本执行有安全面，不进 MVP）。
3. **开机自启**：**首次创建定时任务时询问**用户是否开启（不默认偷偷常驻）。
4. **错过补跑**：周期任务错过 → **补跑最近一次**（不把睡一晚错过的 N 次全补，避免刷屏），随后重算下一个未来触发点。
5. **记忆引用**：本期推进**不引用** `reference-openclaw` / `feedback-relay-desktop-vs-cli-channel` 两条记忆（文件保留，不删）。方案中相关措辞暂不清理，结论以实测 / 桌面版真实实现（§9.5）为准。
